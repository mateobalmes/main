The v7 → v8 migration

"Strongly preferred" in the posting, and named as a responsibility. So it's a real programme, not hypothetical. You haven't done this specific one — but the reason these fail isn't technical.

What actually changes between v7 and v8

Rafael, or as a follow-up to the migration question.

  • v7 = conventional relational DB
  • v8 = Snowflake cloud DB + local staging
  • writes go through staging, not direct
  • custom SQL and direct writes need rebuilding
  • scale is the business case
  • not an upgrade, a re-platform
The detail

The change. v7 runs on a conventional relational database — Oracle, PostgreSQL, SQL Server. v8 re-platforms onto a Snowflake cloud database, keeping a local database for staging and transient data. Adobe calls it full federated data access.

Why it's more than a version bump. In v7, workflows write straight to tables. In v8 those writes go through a staging mechanism, because Snowflake doesn't behave like a traditional transactional database. So workflows built with custom SQL or direct writes often need refactoring rather than lifting across. Custom schemas and custom code need review, not migration.

What you'd actually do. Inventory every workflow, custom schema, integration and script. Flag standard versus custom. Rebuild the custom ones, re-point integrations, re-establish sending reputation if the infrastructure changes. Then test in parallel, cutover, hypercareHypercareThe heightened-support window right after cutover — extra monitoring, a standing war room, fast rollback ready, usually a few weeks until the new platform behaves normally., steady state.

Building audiences in Classic

Mechanically it's the Query activity inside a workflow, using the query editor. That's your "build audience." The real differences from AJO are conceptual.

The one concept to nail: targeting vs filtering dimension

This is the biggest conceptual gap from AJO, and interviewers like it because it separates people who've read about Classic from people who've used it. Every query has two dimensions:

  • Targeting dimension — what comes out. Recipients, operators, subscribers, contract beneficiaries.
  • Filtering dimension — what you filter on.

The canonical example: to find clients holding a life-insurance policy over five years, you target Clients and filter on Contract holder. The thing you filter by isn't the thing you send to.

Why this matters for your answer: in AEP everything resolves to a profile. In Classic you can target one entity and filter on another, because it's a relational model with real joins. For an airline — bookings, itineraries, loyalty accounts, passengers on one booking — that's not academic. It's exactly why Campaign is still carrying the volume.

Boeing vs Airbus, if it comes up

  • control authority is the real split
  • Airbus: hard envelope, sidesticks, static thrust levers
  • Boeing: pilot has final say, linked yokes, moving throttles
  • Airbus's commercial weapon is commonality
  • one type rating across the A320 family
The detail

The philosophical split is control authority. Airbus fly-by-wire enforces a hard flight envelope — the aircraft won't let you exceed its limits. Boeing gives the pilot final authority with soft limits that can be overridden. Everything else follows from that: Airbus sidesticks aren't mechanically linked between pilots, Boeing yokes are; Airbus autothrust levers sit static in detents, Boeing autothrottles physically move.

Commercially, Airbus's real weapon is commonality — one type rating across the whole A320 family, cross-crew qualification up to the A330 and A350. It's a training-cost argument, which is how it wins fleet decisions.

Spotter details: the 737's flat-bottomed nacelles exist because it sits too low for a round one. The 787's raked wingtips and serrated chevrons are what make it quiet. The GE90 on a 777-300ER has a fan about as wide as a 737 fuselage. The A320's power transfer unit barks on the ground.

Air Canada spans both: 737 MAX 8, 777, 787 on the Boeing side; A220, A320 family, A330 on Airbus; E175s at Express.
